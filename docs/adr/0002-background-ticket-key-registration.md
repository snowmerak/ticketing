# ADR 0002: 백그라운드 티켓 키 등록과 읽기 전용 readiness

- 날짜: 2026-09-24
- 상태: 채택·구현 (로컬 V1)
- 결정 권한: 프로젝트 사용자
- 관계: [ADR 0001](./0001-ephemeral-ticket-signing-keys.md)의 요청 시 회전·시작 시 등록 성공 필수 부분을 대체한다. Ed25519, `kid`, 공개키 Redis 분리는 유지한다.

## 배경

기존에는 `/readyz`가 만료된 키를 발견하면 새 키를 생성·등록할 수 있었고, 키 Redis가 시작 시 불가하면 HTTP 프로세스 자체가 시작되지 않았다. 따라서 상태 확인 요청이 쓰기를 유발하며, 의존성 복구 뒤에도 프로세스를 다시 시작해야 했다.

## 결정

`serve`의 취소 가능한 백그라운드 작업만 키 생성·등록·교체를 수행한다. 공개키를 등록한 뒤에만 개인키를 활성화한다. 서명 가능 기간의 마지막 10%(최대 1분)에 대체 키를 미리 등록하고, 실패하면 같은 후보 키와 `kid`로 제한 시간 있는 등록을 jitter가 있는 지수 백오프(최대 5초)로 계속 재시도한다. 이전 활성 키는 수명 내에서 유지한다. 현재 공개키가 유실되면 최대 5초 간격의 점검에서 같은 키를 재등록한다.

`/readyz`는 로컬 활성 키와 공개키 조회만 확인하며 생성·등록하지 않는다. 키 Redis가 시작 시 불가해도 HTTP는 뜨지만, 등록 전 readiness는 503이다. 서명이 필요한 발급·갱신은 등록된 유효 키가 없거나 조회가 실패하면 `TICKET_KEY_UNAVAILABLE`(503)로 닫는다. 서명이 불필요한 직접 입장은 계속 가능하다. 미등록 상태의 대기표 요청은 queue sequence나 epoch를 만들지 않는다.

## 영향과 한계

키 등록의 성공 응답이 유실될 수 있으므로 같은 키로 재시도하며 어댑터의 동일 값 `SETNX` 처리가 멱등성을 제공한다. 각 시도는 `DEPENDENCY_TIMEOUT`으로 제한되고 프로세스 종료 시 취소된다. 반복 실패와 회복은 상태 전환 시 로그를 남긴다. 키가 만료될 때까지 새 키를 등록하지 못하면 해당 인스턴스의 서명은 503이지만, 정상 키 Redis와 다른 인스턴스의 서명까지 강제로 중단하지 않는다.

현재 프로세스가 평상시 보유한 활성 공개키는 재등록할 수 있지만, 교체 구간에는 새 키 등록을 우선한다. 이전 인스턴스 또는 이미 교체된 키의 공개키 유실은 복구할 수 없고, 유실된 구 키로 서명한 미만료 토큰도 자동 복구를 보장하지 않는다. 레지스트리 손실이나 충돌을 무조건 덮어쓰지 않는다. 전역 무손실 failover, 긴급 폐기와 운영 ACL 검증은 별도 과제다.
